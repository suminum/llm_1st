# 검증도구

자료를 고친 뒤에는 **반드시** 여기 도구를 돌리세요.
JS자료·React자료·HTMLCSS자료를 만들면서 "다 됐다" 고 선언한 뒤에도
매 라운드 새 오류가 나왔습니다. 사람 눈으로는 안 잡힙니다.

이 자료를 쓰면서 **실제로 잡힌 오류가 38건**입니다(기계 26 + 심층검토 12). 아래 「이 도구가 잡은 것」을 보세요.
마지막 4건은 **09단원(종합 실습)을 넣으면서** 나왔습니다. 단원 하나를 더하면 도구도 같이 고쳐야 합니다.

### verify_claims.js — 정답 블록의 주장

`verify.js` 는 `// 에러:` 로 선언한 실수 예제를 본다. 그런데 정답 블록 안에는

```
// 2) error TS2322: Type 'number' is not assignable to type 'string'.
```

처럼 **서술로 적어 둔 주장**이 따로 48건 있다. 주석이라 아무도 안 돌려 본다.
그래서 주장마다 재현 코드를 달고 진짜로 돌린다.

```
// 2) error TS2322: Type 'number' is not assignable to type 'string'.
//    재현: const price: string = 4000;
```

- 재현 코드는 **그것만으로 돌아가는 완결된 조각**이어야 한다(원본에 붙이지 않고 따로 떼어 검사).
- 여러 줄이면 `// 재현:` 만 쓰고 다음 줄부터 코드를 적는다.
- 재현이 불가능하면 `// 재현: 없음 — 이유` 로 면제하되 이유를 반드시 쓴다.
- 한글로 **시작**하는 줄, `[` `<` `(` `:` `?` `!` `.` `★` `→` 로 시작하는 줄에서 코드 블록이 끝난다.

### check_exercises.js — 채점 기준이 사실인가

자료는 학생에게 "이 명령이 조용해지면 다 맞은 것" 이라고 약속한다.
그 약속이 사실인지 기계로 확인한다. **처음 돌렸을 때 거짓으로 드러났다** —
`npm run check` 는 당시 107문항 중 18개(17%)만 잡고, 01·02단원은 0개였다.
그래서 `grade.js`(출력 대조 채점)를 만들고 자료의 안내를 전부 고쳤다.

**현재는 138문항 중 21개(15%).** 09단원을 넣어서 문항이 늘었지만 비율은 그대로다.
종합01~03은 데이터에 타입이 이미 붙어 있어서 검사로 **0개** 잡힌다. 채점은 `grade.js` 가 한다.

### grade.js — 채점

연습문제를 실제로 돌려서 문제의 `기대 출력` 과 줄 단위로 맞춘다.
`--answer` 를 주면 **문제의 기대 출력 ↔ 정답 파일의 실제 출력**을 대조한다.
어긋나면 학생이 정답대로 풀어도 채점에서 틀린 것으로 나오므로 반드시 통과해야 한다.
(현재 7단원 117줄 전부 일치)

## verify.js — 네 트랙

### 트랙 1 · `// 출력:` 대조

`node` 로 실제로 돌려서 stdout 을 걷고, 파일 안 선언과 줄 단위로 맞춥니다.

```ts
console.log(menu.name);
// 출력: 라떼          ← 이 줄이 실제 결과와 다르면 실패
```

`// 출력:` 은 **코드 다음 줄에 단독으로** 씁니다. 같은 줄에 붙이면 수집이 안 되고 경고가 납니다.

### 트랙 2 · `// 에러:` 대조 ★ 이 자료의 핵심

주석 처리된 '틀린 코드' 를 **한 블록씩 되살려** 임시 파일을 만들고 `tsc` 에 겁니다.

```ts
// 에러: TS2322 Type 'string' is not assignable to type 'number'.
// const wrongPrice: number = "4000";
//
// 실수: 여기부터는 설명입니다(코드로 안 봄)
```

- `// 에러:` 다음의 연속된 주석 줄이 '되살릴 코드' 입니다.
- 빈 줄이나 `실수:` · `고치면:` · `설명:` · `참고:` 로 시작하는 줄에서 끊깁니다.
- `// 에러:` 를 여러 줄 연달아 쓰면 "한 블록이 에러를 여러 개 낸다" 는 뜻입니다.
- **선언했는데 안 나도 실패**입니다. 자료가 거짓말을 하고 있는 것이니까요.
- 선언 안 한 에러가 나도 실패입니다.

### 트랙 2 의 구멍 — 앞 40자만 비교하던 문제 (고침)

선언한 메시지와 실제 메시지를 대조할 때 **앞 40자만** 보고 있었다.
그런데 TS 에러 메시지는 타입 이름이 뒤쪽에 온다.

```
선언  Property 'toUpperCase' does not exist on type 'number'.
실제  Property 'toUpperCase' does not exist on type '4000'.
      └────────── 앞 40자 (여기까지만 봤다) ──────────┘
```

앞 40자가 `Property 'toUpperCase' does not exist on` 까지라서 **타입 이름이 비교 범위 밖**이었다.
그래서 `02/개념02_추론.ts:32` 가 `'number'` 라고 적어 둔 채 통과했다.
`const price2 = 4000;` 은 리터럴 타입 `4000` 이 되므로 실제로는 `'4000'` 이 나온다.
정작 같은 파일 226줄이 "메시지에 'string' 이 아니라 '"서울"' 이라고 나오는 것에 주목하세요" 라고
바로 그 성질을 가르치고 있었다.

지금은 **선언한 메시지 전체**를 비교한다(`slice(0, 40)` 제거, 2곳).
전체 비교로 바꿔도 나머지 169건은 그대로 통과하므로 오탐은 없다.

> 짧게 자르는 비교는 '틀린 것을 못 찾는' 게 아니라 **틀린 줄 모르고 초록불을 켠다.**
> 28번 항목과 같은 종류다.

> JS자료에서 바로 이 자리가 구멍이었습니다.
> "주석 처리된 실수 예제는 실행이 안 되니 틀려도 안 잡힌다" 여서
> 실제로 5건이 틀린 채로 나갔습니다. 그 구멍을 막은 것이 이 트랙입니다.

### 트랙 2-b · '일부러 틀린 파일'

머리글에 `일부러 틀린 파일` 이라고 적힌 파일은 코드가 **살아 있습니다.**
(`01단원/틀린예제/타입이_틀린_파일.ts`)

이때는 `// 에러:` **바로 다음의 살아 있는 코드 줄**에서 그 에러가 나야 합니다.
그리고 `node` 로는 멀쩡히 돌아가야 합니다. 그게 그 파일의 존재 이유입니다.

### 트랙 3 · 프로젝트 전체 `tsc --noEmit`

**언제나 조용해야 합니다.** 이게 이 자료의 기준선입니다.

기준선을 지키려고 `tsconfig.json` 에서 둘을 뺐습니다.

- `**/틀린예제` — 일부러 틀린 파일
- `**/연습문제.ts` — 안 푼 상태에서 걸리는 게 정상 (`npm run check` 로 따로 봄)

### 트랙 4 · ✏️ 정답 블록 실행 대조

파일 맨 아래 `직접 해보기 정답` 은 전부 주석이라 실행이 안 됩니다.
여기서는 **정답 코드를 뽑아 원본 뒤에 붙여 실제로 돌립니다.**

```
// 1) console.log(greet("홍길동").length);    // 출력: 10
```

- `// N)` 로 항목을 나누고, 각 항목을 `{ }` 로 감싸 이름 충돌을 막습니다.
- 인라인 `// 출력:` 이 붙은 줄만 대조합니다.
- 코드/해설 구분은 **"코드처럼 시작하고 코드처럼 끝나는 줄"** 입니다
  (`const`·`function`·`console.log`… 로 시작하고 `;`·`{`·`}`·`,` 로 끝남).

> 처음에는 "`=>` 가 있으면 코드" 로 판정했다가,
> `(n) => fn(n) 이라고 쓸 필요가 없습니다` 같은 **한글 해설이 코드로 붙어** 실행이 깨졌습니다.
> 시작만 보면 `prices[0] 이 number 라서...` 도 코드로 잡힙니다. 그래서 양쪽 끝을 다 봅니다.

## audit.js — 구조 감사

기계가 볼 수 있는 것만 봅니다. 전부 다른 자료에서 실제로 사고가 났던 항목입니다.

- ✏️ 번호가 1부터 빠짐없이 이어지는가

## 09단원(종합 실습)은 다르게 다룬다

다른 단원은 `연습문제.ts` **하나**에 문제가 다 있다. 09단원은 **파일마다 한 세트**다.
그리고 종합04만 브라우저라서 다른 폴더에 있다.

| | 01~06·08 | 07 | 09 |
| --- | --- | --- | --- |
| 문제 파일 | `연습문제.ts` 1개 | `연습문제.tsx` 1개 | `종합01~03.ts` + `종합04.tsx` |
| 어디에 | 단원 폴더 | `실습프로젝트/src/07_.../` | 단원 폴더 **+** `실습프로젝트/src/09_.../` |
| 개념 파일 | 있음 | 있음 | **없음** |

그래서 도구들은 09단원에서 **두 폴더를 본다**(`audit`·`class`·`exercises`·`stats`).
새 도구를 쓸 때 단원을 훑는다면 이 두 번째 폴더를 빠뜨리지 마세요.

### tsconfig — 종합 문제 파일은 한 줄씩 적어야 한다

문제 파일은 TODO 가 비어 있어서 검사가 시끄럽고, 정답 파일은 **언제나 조용해야** 한다.
그런데 TypeScript 의 `exclude` glob 에는 **부정이 없다.** `**/종합0*.ts` 라고 쓰면
`종합01_주문_관리_정답.ts` 까지 같이 빠져서, **정답이 틀려도 아무도 모른다.**

그래서 `tsconfig.json` 은 문제 파일 셋을 이렇게 하나씩 적는다.

```json
"exclude": [
  "**/연습문제.ts",
  "09_종합_실습/종합01_주문_관리.ts",
  "09_종합_실습/종합02_재고_보고서.ts",
  "09_종합_실습/종합03_서버_응답.ts"
]
```

**종합 실습을 추가하면 이 목록에도 넣으세요.** 빠뜨리면 `npm run typecheck` 가
문제 파일의 TODO 때문에 시끄러워지므로 바로 드러납니다.

## 이 도구가 잡은 것 (자료를 쓰는 동안)

사람이 추측으로 쓰면 반드시 틀립니다. 아래는 전부 **쓸 때는 맞다고 생각했던 것**입니다.

| # | 내가 쓴 것 | 실제 |
| --- | --- | --- |
| 1 | `"3" + 3000` 은 TS 가 막는다 | **안 막는다.** 이어붙이기는 정당한 연산 |
| 2 | `any * 2` 는 `any` | **`number`.** any 는 점(`.`)을 따라갈 때만 번짐 |
| 3 | 속성 빠짐 = 넘길 때 `TS2345` | **`TS2741`.** 담든 넘기든 같음 |
| 4 | `let` 은 유니온 그대로 | **좁혀진다.** const/let 문제가 아니라 '값이 보이느냐' |
| 5 | 매개변수 적은 함수는 함수 타입에 못 들어감 | **들어간다** |
| 6 | `cafe.nmae` → 제안 나옴 | **안 나옴**(TS2339). `pirce` 는 나옴(TS2551) |
| 7 | `"...".toFixed` → TS2339 | **TS2551.** 문자열에 옛날 `fixed` 가 있어서 |
| 8 | `Map.get(...) + 1` → TS18048 | **TS2532**(이름 없는 결과라 `Object`) |
| 9 | `useState(null)` 후 객체 대입 → TS2345 | **TS2353**(updater 오버로드 쪽으로 맞춰 봄) |

### 28번이 왜 무서운가 — 검사기가 조용히 통과시킨다

종합04는 문제 4·5·6이 `Page()` **안에** 있어서 두 칸 들여써져 있다.
`^\/\/ ───── 문제` 는 column 0 만 보므로 이 셋을 못 본다. 그러면 audit 은
"문제 1,2,3 이 있고 정답에도 1,2,3 이 있네" 하고 **통과시킨다.**
빠진 것을 못 찾는 게 아니라, **빠진 줄 모르고 초록불을 켠다.**

`기대 화면:` 수집도 같은 문제였다. `audit`·`stats`·`class`·`exercises`·`grade`
**다섯 도구 전부** 같은 정규식을 쓰고 있었다. 지금은 전부 `^\s*\/\/ ───── 문제` 다.

> 새 도구를 쓸 때 문제 마커를 찾는다면 **반드시 `^\s*`** 를 넣으세요.

**표본 10건을 손으로 돌려 봤을 때 1건이 틀렸고, 전수로 돌리니 6건이 더 나왔다.**
그리고 **자동 검사를 전부 통과한 뒤에도 검토 라운드마다 나왔다**(1라운드 5건, 2라운드 3건, 3라운드 4건).
"몇 개 찍어 봤는데 맞더라" 도, "검증기 다 통과했다" 도 끝이 아니다.

### check_density.js 의 함정 — 지표가 난이도와 반대로 움직인다

문제의 '무게'(지문+코드+출력)를 재면 **기본이 응용보다 무겁게** 나온다.
"도와주는 양을 뒤로 갈수록 줄인다" 는 설계가 그대로 반영된 것이라, 무거운 것이 쉬운 것이다.
2라운드에서 4단원이 '역전 의심' 으로 걸렸지만 **전부 아티팩트였다.**
이 도구는 '열어 볼 곳' 목록으로만 쓰고 판정은 직접 할 것.
