# 검증 도구

**학생용이 아닙니다.** 자료를 고치거나 늘릴 때 쓰는 도구입니다.

이 자료의 `// 콘솔:` · `// 화면:` · `기대 결과` 는 전부 **실제로 실행해서 맞춘 값**입니다.
손으로 예상해서 적은 것이 하나도 없습니다. 그 상태를 유지하려면 자료를 고칠 때마다
아래를 돌려야 합니다.

---

## 처음 한 번만 — 준비

```
cd _검증도구
npm i puppeteer-core @babel/core @babel/preset-react
```

`@babel/core` 는 `check_practice.js` 가 씁니다. 이게 없으면
`Cannot find module '@babel/core'` 로 그 도구만 안 돕니다.

★ `npm init -y` 는 하지 마세요. 폴더 이름이 `_검증도구` 라 npm 이
`Invalid name: "_검증도구"` 로 거절합니다. **`npm i` 만 하면 됩니다.**
(이 폴더에는 `package.json` 과 `package-lock.json` 이 이미 있으니
 그냥 `npm i` 만 치면 같은 버전이 그대로 깔립니다)

`puppeteer-core` 는 **이미 설치된 크롬**을 조종합니다. 크롬을 새로 받지 않습니다.
경로는 각 스크립트 맨 위에서 **OS 를 보고 알아서 고릅니다**(Windows·macOS·Linux).
설치 위치가 다르면 환경변수로 넘기세요.

```
CHROME_PATH="/내/크롬/경로" node verify_jsx.js
```

## ★ macOS 에서 고칠 때 — 한글 파일명 주의

macOS 는 한글 파일명을 **NFD(자모 분해형)** 로 돌려줍니다.
그래서 `/^개념/` 같은 정규식이나 `find -name '개념*'` 이 **아무것도 못 찾습니다.**

이 도구들은 파일명을 쓰는 자리마다 `.normalize("NFC")` 로 되돌려 놓았습니다.
새 도구를 만들 때도 **`fs.readdirSync()` 결과를 바로 정규식에 넣지 마세요.**

```js
const base = path.basename(full).normalize("NFC");   // ← 이렇게
```

안 하면 도구가 **에러 없이 "0개 검사, 문제 없음" 을 냅니다.** 가장 위험한 실패 방식입니다.

## 자료를 고칠 때 지킬 것

1. **예상 출력을 손으로 적지 마세요.** 반드시 실행해서 맞추세요.
   JS자료를 만들 때 이걸 어겨서 부동소수점 오기, 정렬이 안 되는 코드를 "된다" 고 쓴 사고가 났습니다.
2. **한 번 통과했다고 넘기지 마세요.** 타이머·`fetch` 를 쓰는 파일은 **여러 번** 돌리세요.
   이 자료에서도 `01/개념03` 이 가끔만 터지는 버그를 그렇게 잡았습니다.
3. **일부러 내는 경고**는 파일에 이렇게 선언하세요. 그러면 실패로 치지 않습니다.
   ```js
   // 검증: 경고허용 Each child in a list should have a unique "key" prop
   ```
   선언해 놓고 **실제로는 안 나면 실패로 잡힙니다.** 자료가 거짓말하는 것을 막기 위해서입니다.
4. **일부러 비워 두는 root** 는 이렇게 선언하세요.
   ```js
   // 검증: 빈root허용 silentRoot
   ```
5. `check_forward.js` 와 `check_xref.js` 는 **오탐이 섞여 나옵니다.** 자동으로 고치지 말고
   하나씩 직접 판정하세요. 실제로 230건 인용 중 진짜 오류는 1건이었습니다.
6. 항목 수(✏️·문제)를 바꾸면 `stats.js` 를 다시 돌려 **`수업_진행_가이드.md` 의 표를 함께 고치세요.**
