이 파일은 문단 안의 단어에 뜻을 붙이는 태그들을 다룹니다. strong b em i mark small del ins sub sup q blockquote 입니다. 개수가 많아 보이지만 모양이 아니라 뜻으로 고른다는 원칙 하나로 전부 통합니다.

섹션 1 — strong 과 b

둘 다 굵게 보입니다. strong 은 중요하다는 뜻이고, b 는 굵게 그려라는 모양 지시입니다.

섹션 2 — em 과 i

둘 다 기울어 보입니다. em 은 힘주어 읽으라는 뜻이고, i 는 기울여 그려라는 모양 지시입니다.

실제 결과

나는 오늘 간다.

배 이름은 이순신함입니다.

strong 과 em 은 겹쳐 쓸 수 있습니다. <strong><em>글자</em></strong> 처럼 쓰면 굵으면서 기울어집니다. 두 태그의 효과가 둘 다 적용되기 때문입니다.

✏️ 직접 해보기 2 — 위 상자의 첫 줄을 <p><em>나는</em> 오늘 간다.</p> 로 바꿔 보세요. 기울어지는 단어가 옮겨 가고, 문장을 소리 내어 읽었을 때 뜻이 달라지는지 확인해 보세요.

섹션 7 — q 와 blockquote

남의 말을 옮길 때 씁니다. q 는 문장 안의 짧은 인용, blockquote 는 덩어리로 떨어진 긴 인용입니다.

섹션 8 — 자주 하는 실수

여기 실수들은 화면이 원하는 대로 나오기 때문에 특히 안 들킵니다. 에러도 물론 나지 않습니다.

실수 1 — 굵게 보이고 싶어서 strong 을 씀
<p><strong>메뉴 안내</strong></p>

제목을 굵게 만들고 싶어서 strong 을 썼습니다. 굵어지기는 합니다. 하지만 이건 제목이므로 <h2> 를 써야 합니다. strong 으로 쓴 제목은 목차에 잡히지 않습니다. 개념01 섹션 5 에서 본 것과 똑같은 종류의 잘못입니다.

실수 2 — 문단 전체를 strong 으로 감쌈
<p><strong>모든 문장이 다 중요합니다. 안 중요한 문장이 없습니다.</strong></p>

전부 강조하면 아무것도 강조되지 않습니다. 화면 낭독기에게도 문단 전체가 강조로 들려서 오히려 알아듣기 어려워집니다. 강조는 한 문단에 한두 군데면 충분합니다. 아래가 실제 결과입니다.

문단 전체를 감싼 실제 결과

모든 문장이 다 중요합니다. 안 중요한 문장이 없습니다.

실수 3 — 들여쓰려고 blockquote 를 씀
<blockquote>여기는 그냥 제 설명입니다</blockquote>

왼쪽으로 40px 들여져서 보기에는 좋습니다. 하지만 뜻은 "이 문장은 남이 한 말을 옮긴 것" 이 됩니다. 내 말인데 남의 말이라고 표시한 셈입니다. 아래가 실제 결과입니다.

실수 4 — 줄만 긋고 싶어서 del 을 씀
<del>오늘의 할 일</del>

지운 적이 없는 글에 del 을 붙이면 "이 내용은 삭제되었다" 는 뜻이 붙습니다. 화면 낭독기는 "삭제됨" 이라고 알려 줍니다. 장식으로 줄을 긋고 싶다면 09단원의 text-decoration 을 쓰세요.

실수 5 — strong 을 string 으로 씀
<string>중요합니다</string>

string 이라는 태그는 없습니다. 오타인데도 에러가 나지 않습니다. 브라우저는 모르는 태그를 없는 셈 치고 안의 글자만 그립니다. 그래서 굵어지지 않은 보통 글자가 나옵니다. "왜 안 굵어지지?" 싶으면 태그 이름 철자부터 확인하세요.

철자를 틀린 실제 결과

중요합니다

── 정리 ──

1. strong(중요) 과 b(굵게), em(억양) 과 i(기울임) 은 화면이 같고 뜻이 다릅니다.

2. 차이는 화면 밖에 있습니다. 화면 낭독기, 검색, 나중의 CSS 세 곳에서 드러납니다.

3. mark 는 형광펜, small 은 곁다리 말입니다.

4. del 은 지운 내용, ins 는 새로 넣은 내용입니다.

5. sub 는 아래첨자, sup 는 위첨자입니다.

6. q 의 따옴표는 브라우저가 그려 준 것이라 글자가 아닙니다. 태그에 뜻이 들어 있다는 증거입니다.

7. 태그는 뜻으로 고르고, 모양은 CSS 로 바꿉니다.
