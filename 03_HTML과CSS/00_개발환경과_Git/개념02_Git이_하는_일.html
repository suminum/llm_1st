개념 02 — Git 이 하는 일

00단원 · 개발환경과 Git

터미널에서 같이 따라 하세요. 읽기만 하면 안 남습니다.

바탕화면에 깃연습 이라는 빈 폴더를 하나 만들고 거기서 하세요. 이 자료 폴더 안에서는 하지 마세요. 왜 안 되는지는 섹션 1에 있습니다.

아래 결과는 실제로 쳐 본 것입니다. 커밋 번호(ae4c0c2 같은)만 여러분 것과 다릅니다.

섹션 1 — 기록을 시작합니다

폴더 하나를 정해서 "여기를 기록해라" 라고 말해 줍니다. 딱 한 번만 합니다.

$ git init Initialized empty Git repository in C:/Users/…/깃연습/.git/

.git 이라는 숨은 폴더가 하나 생깁니다. 여기에 기록이 전부 들어갑니다. 절대 열어서 고치지 마세요. 이 폴더를 지우면 기록이 통째로 사라집니다.
★ 반대로, "Git 을 그만 쓰고 싶다" 면 .git 을 지우면 됩니다. 파일은 그대로 남습니다.

이 자료 폴더 안에서 하면 안 되는 이유

이 자료는 이미 Git 으로 관리되고 있습니다. 그 안에서 또 git init 을 하면 저장소 안에 저장소가 생겨 아주 헷갈립니다. 빈 폴더에서 연습하세요.

✏️ 직접 해보기 1 — 바탕화면에 깃연습 폴더를 만들고, 터미널에서 그 폴더로 가서 git init 을 치세요. 그리고 숨은 파일 보기를 켜서 .git 이 생겼는지 보세요.

섹션 2 — 자리가 세 군데입니다

Git 을 헷갈리게 만드는 것은 명령이 아니라 자리입니다. 파일이 있을 수 있는 자리가 셋입니다.

작업 폴더 담는 곳 저장소 (내가 고치는 곳) (이번에 기록할 것) (기록으로 남은 것) │ │ │ │ ── git add ──→ │ │ │ │ ── git commit ──→ │ │ │ │

"add 를 왜 또 해요?" — 고친 파일이 10개인데 그중 3개만 기록하고 싶을 때가 있기 때문입니다. 장바구니에 담는 것과 계산하는 것이 나뉜 것과 같습니다.
★ 지금은 git add . (전부 담기) 로만 써도 됩니다. 나뉘어 있다는 것만 알아 두세요.

섹션 3 — 만들고 담고 기록합니다

index.html 파일을 하나 만들고 안에 한 줄만 씁니다.

<h1>안녕하세요</h1>

그리고 git status 를 칩니다.

$ git status On branch main No commits yet Untracked files: (use "git add <file>..." to include in what will be committed) index.html nothing added to commit but untracked files present (use "git add" to track)

Untracked — "이런 파일이 있는데 나는 얘를 모른다" 는 뜻입니다. Git 은 폴더 안의 파일을 자동으로 챙기지 않습니다. 내가 알려 줘야 합니다.
★ 그리고 괄호 안에 다음에 뭘 할지 적혀 있습니다. use "git add <file>...". Git 은 거의 항상 다음 할 일을 알려 줍니다. 영어라고 건너뛰지 말고 읽으세요. 답이 거기 있습니다.

git status 는 말이 깁니다. --short 를 붙이면 짧게 나옵니다.

$ git status --short ?? index.html

담고, 다시 봅니다.

$ git add index.html $ git status --short A index.html

이제 기록합니다.

$ git commit -m "첫 페이지를 만들었습니다" [main (root-commit) ae4c0c2] 첫 페이지를 만들었습니다 1 file changed, 1 insertion(+) create mode 100644 index.html

-m 은 message 입니다. 무엇을 왜 했는지를 적습니다.
ae4c0c2 는 이 기록에 붙은 번호입니다. 내용에서 나온 값이라 여러분 것은 다릅니다. root-commit 은 "첫 기록" 이라는 뜻입니다.

$ git log --oneline ae4c0c2 첫 페이지를 만들었습니다

✏️ 직접 해보기 2 — 위 순서를 그대로 해 보세요. git add 전후로 git status --short 를 쳐서 ?? 가 A 로 바뀌는 것을 눈으로 보세요.

섹션 4 — status 의 기호 읽는 법

--short 로 보면 왼쪽에 글자 두 개가 붙습니다. 이 두 칸이 각각 다른 자리를 가리킵니다.

첫째 칸 = 담는 곳의 상태 둘째 칸 = 작업 폴더의 상태 ?? index.html 양쪽 다 모름 → 새 파일인데 아직 add 안 함 A index.html 담김 (새 파일) → add 했다 M index.html 작업 폴더만 고쳐짐 → 고쳤는데 add 안 함 M index.html 담긴 것도 고쳐짐 → 고치고 add 했다 MM index.html 담고 나서 또 고쳤다 → 둘 다 있음 UU index.html 충돌 (개념05)

M 과 M 은 다릅니다. 앞에 공백이 있으면 "아직 안 담았다", 뒤에 공백이 있으면 "담았다" 입니다.
★ 이걸 모르면 git commit 을 했는데 왜 안 들어갔는지 모릅니다. 담기지 않은 것은 커밋되지 않습니다.

✏️ 직접 해보기 3 — index.html 에 한 줄을 더 넣고 저장한 뒤 git status --short → git add . → 다시 git status --short 를 쳐서 기호가 어떻게 바뀌는지 보세요.

섹션 5 — 무엇이 달라졌는지 봅니다

파일에 한 줄을 더 넣었습니다. git diff 로 무엇이 바뀌었는지 봅니다.

$ git diff diff --git a/index.html b/index.html index 6944b17..87d06c9 100644 --- a/index.html +++ b/index.html @@ -1 +1,2 @@ <h1>안녕하세요</h1> +<p>처음 만든 페이지입니다.</p>

앞의 네 줄은 지금 안 봐도 됩니다. 중요한 것은 마지막 두 줄입니다.
+ 로 시작하면 새로 생긴 줄, - 로 시작하면 없어진 줄, 아무것도 없으면 그대로인 줄입니다.

★ git diff 는 아직 안 담은 것만 보여 줍니다. git add 를 한 뒤에 git diff 를 치면 아무것도 안 나옵니다. 고장이 아닙니다. 담긴 것을 보려면 git diff --staged 입니다.
이것도 섹션 4의 "자리가 둘" 때문입니다.

✏️ 직접 해보기 4 — 파일을 고치고 git diff → git add . → git diff → git diff --staged 순서로 쳐 보세요. 어느 것이 언제 비는지 확인하세요.

이렇게 쓰면 안 됩니다

★ 한 번에 하나씩 커밋하세요. "로그인도 고치고 색도 바꾸고 파일도 지웠습니다" 는 메시지를 쓸 수 없습니다. 메시지가 안 써지면 한 번에 너무 많이 한 것입니다.

섹션 7 — 자주 하는 실수

[실수 1] add 를 하고 commit 을 안 함

담기만 하고 계산을 안 한 것입니다. git log 에 아무것도 안 나옵니다. git status --short 에 A 나 M 가 남아 있으면 이 경우입니다.

[실수 2] 고치고 add 를 안 한 채 commit

nothing added to commit 이 나옵니다. 고친 것은 있는데 담은 것이 없다는 뜻입니다. 섹션 4를 다시 보세요.

[실수 3] -m 을 빼먹음

git commit 만 치면 편집기가 열립니다. 검은 화면에 글자가 잔뜩 나와서 놀라는 학생이 많습니다.
빠져나오는 법: Esc → :q! → Enter
★ 이건 vim 이라는 편집기입니다. 겁먹을 필요 없습니다. 나오는 법만 알면 됩니다.

[실수 4] 이 자료 폴더에서 git init

섹션 1 그대로입니다. 빈 폴더에서 연습하세요.

[실수 5] .git 폴더를 지움

기록이 전부 사라집니다. 되돌릴 방법이 없습니다. 숨은 폴더는 건드리지 마세요.

[실수 6] 줄 끝 문자 경고

warning: LF will be replaced by CRLF 같은 것이 나올 수 있습니다. 고장이 아닙니다. 윈도우와 리눅스가 줄 바꿈을 다르게 적어서 나는 안내입니다. 수업에서는 그냥 넘어가도 됩니다.

정리

  • git init 은 폴더마다 한 번. .git 숨은 폴더가 생깁니다.
  • 자리가 셋입니다 — 작업 폴더 → (add) → 담는 곳 → (commit) → 저장소
  • git status --short 의 왼쪽 두 칸이 각각 담는 곳과 작업 폴더입니다. M 과 M 은 다릅니다.
  • git diff 는 안 담은 것만 보여 줍니다. 담긴 것은 --staged.
  • 커밋 메시지는 무엇을 했는지. 메시지가 안 써지면 한 번에 너무 많이 한 것입니다.
  • ★ Git 의 오류 메시지는 다음에 할 일을 알려 줍니다. 끝까지 읽으세요.
