개념 04 — GitHub 에 올리기

00단원 · 개발환경과 Git

GitHub 계정이 필요합니다. https://github.com 에서 가입하세요. 무료입니다.

가입할 때 쓴 메일을 개념01의 user.email 과 같게 하세요. 다르면 내가 한 작업으로 안 세어 줍니다.

아이디는 나중에 이력서에 적을 것이라 생각하고 지으세요. hong-gildong 은 괜찮고 xxx-gamer-1234 는 다시 생각해 보세요.

섹션 1 — 인터넷에 빈 저장소를 하나 만듭니다

GitHub 오른쪽 위 + → New repository 를 누릅니다.

Repository name 깃연습 Description (비워도 됩니다) Public / Private Public 이면 아무나 볼 수 있습니다 ★ 처음에는 Private 으로 하세요 Add a README file ← ★ 체크하지 마세요 Add .gitignore ← ★ 체크하지 마세요 Choose a license ← ★ 고르지 마세요

왜 아무것도 체크하지 말라고 하나 — 체크하면 GitHub 이 파일을 먼저 만들어 버립니다. 그러면 내 컴퓨터의 기록과 GitHub 의 기록이 출발점이 달라져서 첫 push 에서 막힙니다. (섹션 5의 그 오류입니다)
★ 빈 저장소로 만들고 내 것을 밀어 넣는 게 제일 쉽습니다.

Private 으로 시작하세요. 실수로 비밀번호를 올려도 남이 못 봅니다. 포트폴리오로 보여 줄 때 Public 으로 바꾸면 됩니다. (설정 → 맨 아래 Danger Zone → Change visibility)

✏️ 직접 해보기 1 — 깃연습 이라는 이름으로 빈 Private 저장소를 하나 만드세요. 만든 뒤 나오는 안내 화면을 그대로 두세요. 섹션 2에서 씁니다.

섹션 2 — 내 폴더와 이어 줍니다

내 컴퓨터의 깃연습 폴더에게 "인터넷 쪽 주소는 여기다" 라고 알려 줍니다.

$ git remote -v ← 아무것도 없습니다 $ git remote add origin https://github.com/hong/깃연습.git $ git remote -v origin https://github.com/hong/깃연습.git (fetch) origin https://github.com/hong/깃연습.git (push)

origin 은 그냥 별명입니다. 관례로 이렇게 씁니다. remote 는 "멀리 있는 것" 이라는 뜻입니다.
fetch 는 받아올 때, push 는 보낼 때 쓰는 주소입니다. 보통 같습니다.

주소는 GitHub 화면에 그대로 적혀 있습니다. 저장소를 만들면 나오는 안내에 …or push an existing repository 밑에 복사할 수 있게 나옵니다. 손으로 치지 말고 복사하세요.

✏️ 직접 해보기 2 — GitHub 화면의 주소를 복사해 git remote add origin … 을 치고, git remote -v 로 제대로 들어갔는지 보세요.

섹션 3 — 밀어 올립니다 (push)

$ git branch --show-current main $ git push -u origin main To https://github.com/hong/깃연습.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.

-u 는 "앞으로 이 가지는 저기로 보낸다" 고 정해 두는 것입니다. 한 번만 붙이면 됩니다. 다음부터는 git push 만 치면 됩니다.

$ git push To https://github.com/hong/깃연습.git 9e1ad61..f3bec9d main -> main

9e1ad61..f3bec9d 는 "이 커밋부터 이 커밋까지 보냈다" 는 뜻입니다.

가지 이름이 다르면 막힙니다

내 것이 master 인데 GitHub 은 main 을 씁니다. 개념01 섹션4의 init.defaultBranch main 을 안 했으면 여기서 걸립니다.
고치는 법: git branch -m main (지금 가지의 이름을 바꿉니다)

✏️ 직접 해보기 3 — git push -u origin main 을 치고, GitHub 페이지를 새로고침해서 파일이 올라갔는지 보세요.

섹션 4 — ★ 비밀번호를 물어보면

처음 push 할 때 로그인 창이 뜹니다. 여기서 많이 막힙니다.

GitHub 비밀번호는 안 통합니다

Support for password authentication was removed. 같은 말이 나옵니다. 2021년부터 비밀번호로는 안 됩니다.

방법이 둘입니다. 둘 중 하나만 하면 됩니다.

방법 1 — 창이 뜨면 Sign in with your browser (제일 쉽습니다)

윈도우에서 Git 을 깔면 Git Credential Manager 가 같이 깔립니다. push 할 때 창이 뜨고, 거기서 브라우저로 로그인하면 끝입니다. 한 번만 하면 다음부터 안 물어봅니다.

방법 2 — 토큰(Personal Access Token)
GitHub → 오른쪽 위 프로필 → Settings → Developer settings (맨 아래) → Personal access tokens → Tokens (classic) → Generate new token (classic) Note 내노트북 Expiration 90 days Scopes repo 만 체크 → Generate token

나온 글자를 복사해서 비밀번호 자리에 붙여 넣습니다.
★★ 이 글자는 그 화면을 떠나면 다시 못 봅니다. 창을 닫기 전에 복사하세요. 잃어버리면 새로 만들면 됩니다.

★★★ 토큰은 비밀번호와 같습니다

코드에 적지 마세요. 카톡으로 보내지 마세요. 화면 공유할 때 조심하세요.
남에게 보였다 싶으면 바로 지우세요. (Settings → Tokens → Delete) 지우면 그 자리에서 못 쓰게 됩니다.

기억시켜 두는 곳을 확인하려면 — 윈도우는 제어판 → 자격 증명 관리자 → Windows 자격 증명 에 git:https://github.com 이 있습니다. 잘못 저장됐으면 여기서 지우고 다시 하세요.
★ "예전 계정으로 로그인돼요" 의 답이 이것입니다.

✏️ 직접 해보기 4 — push 를 해서 로그인 창을 띄워 보세요. 방법 1로 되면 그걸로 끝입니다. 안 되면 방법 2로 토큰을 만드세요.

섹션 5 — 받아 오기 (clone · pull)

다른 컴퓨터에서 이어서 하려면 통째로 받아 옵니다.

$ git clone https://github.com/hong/깃연습.git 깃연습 Cloning into '깃연습'... done.

clone 은 init + remote add + 내려받기를 한 번에 합니다. git init 을 따로 안 해도 됩니다.

이미 받아 둔 폴더에서 새로 올라온 것만 가져올 때는 pull 입니다.

$ git pull
★★ 남이 먼저 올렸으면 push 가 거부됩니다
$ git push To https://github.com/hong/깃연습.git ! [rejected] main -> main (fetch first) error: failed to push some refs to 'https://github.com/hong/깃연습.git' hint: Updates were rejected because the remote contains work that you do not hint: have locally. This is usually caused by another repository pushing to hint: the same ref. If you want to integrate the remote changes, use hint: 'git pull' before pushing again.
"저쪽에 네가 모르는 게 있다. pull 먼저 해라" 는 뜻입니다.
★ 여기서도 hint: 가 답을 그대로 알려 줍니다.

그래서 pull 을 먼저 합니다. 그런데 —

$ git pull --no-rebase From https://github.com/hong/깃연습.git f3bec9d..5b9d53a main -> origin/main Auto-merging index.html CONFLICT (content): Merge conflict in index.html Automatic merge failed; fix conflicts and then commit the result.

같은 줄을 둘이 고쳤으면 충돌이 납니다. 푸는 법은 개념05 섹션 5에 있습니다. 여기서 그 이야기가 이어집니다.

★ 습관 하나만 들이세요 — 작업 시작 전에 git pull. 그러면 충돌이 훨씬 줄어듭니다.

✏️ 직접 해보기 5 — GitHub 웹에서 파일을 직접 고쳐 커밋하고(연필 아이콘), 내 컴퓨터에서 git pull 로 받아 보세요.

섹션 6 — ★ 절대 올리면 안 되는 것

개념03 섹션6에서 말한 것을 다시 짚습니다. 여기서는 진짜로 공개됩니다.

API 키 · 토큰 ★★★ 돈이 나갑니다 비밀번호 .env 파일 통째로 개인정보 주민번호·전화번호·주소가 든 파일 회사 자료 계약서·고객 명단 node_modules/ 용량만 잡아먹습니다
Public 저장소는 로봇이 항상 훑고 있습니다

AWS 키를 올리면 몇 분 안에 발견되는 일이 실제로 있습니다. 누군가 그 키로 서버를 잔뜩 켜고, 요금은 올린 사람이 냅니다.

★ 그래서 Private 으로 시작하고, .gitignore 를 처음에 만듭니다.
★★ 지워도 옛 기록에 남습니다. 새어 나갔으면 그 키를 폐기하세요. (개념03 섹션6)

올리기 전에 한 번 보는 습관 — git status 로 무엇이 담겼는지 확인하고 밀으세요. 5초면 됩니다.

✏️ 직접 해보기 6 — 내 저장소를 GitHub 웹에서 열어 파일 목록을 눈으로 훑어보세요. 올리면 안 되는 것이 섞여 있지 않습니까?

섹션 7 — 자주 하는 실수

[실수 1] README 를 체크해서 저장소를 만듦

첫 push 가 거부됩니다. 출발점이 달라서입니다. (섹션 1) 이미 그랬으면 git pull origin main --allow-unrelated-histories 로 붙일 수 있습니다.

[실수 2] 비밀번호를 넣고 계속 실패

비밀번호는 안 됩니다. 브라우저 로그인이나 토큰을 쓰세요. (섹션 4)

[실수 3] 토큰을 안 복사하고 창을 닫음

다시 못 봅니다. 새로 만드세요. 흔한 일입니다.

[실수 4] git push 만 치고 커밋을 안 함

Everything up-to-date 가 나오는데 GitHub 에는 아무것도 없습니다. 커밋하지 않은 것은 올라가지 않습니다. push 는 커밋을 보내는 것이지 파일을 보내는 게 아닙니다.

[실수 5] 가지 이름이 master

GitHub 은 main 을 기본으로 씁니다. git branch -m main 으로 바꾸세요. (섹션 3)

[실수 6] pull 안 하고 push 만 하다가 거부됨

섹션 5 그대로입니다. 시작 전에 pull 을 습관으로 만드세요.

정리

  • Git 은 프로그램, GitHub 은 웹사이트입니다. 다른 것입니다.
  • 저장소는 아무것도 체크하지 않고 비어 있게 만듭니다. 처음에는 Private.
  • git remote add origin 주소 → git push -u origin main. -u 는 한 번만.
  • ★ 비밀번호는 안 통합니다. 브라우저 로그인 또는 토큰을 쓰세요.
  • 남이 먼저 올렸으면 push 가 거부됩니다. 시작 전에 git pull.
  • ★★ 키·비밀번호를 올리면 몇 분 안에 발견됩니다. 지워도 기록에 남으니 폐기하세요.
  • 커밋 안 한 것은 push 해도 안 올라갑니다.
