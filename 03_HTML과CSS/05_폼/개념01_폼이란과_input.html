개념 01 — 폼이란 무엇인가, 그리고 input

05단원 · 폼

이 파일에서는 값을 넣을 칸을 처음 만들어 봅니다. 화면에 네모난 칸이 나오면 진짜로 마우스로 눌러서 글자를 쳐 보세요. 칸이 작고 밋밋하게 보이는 것은 정상입니다. 꾸미는 것은 09~10단원입니다. 지금은 모양이 아니라 "이 칸이 무엇을 받는 칸인지" 를 적는 연습만 합니다.

섹션 1 — 폼은 입력칸을 묶는 상자입니다

<form> 은 여러 입력칸을 하나의 묶음으로 만드는 태그입니다. 자기 자신은 화면에 아무것도 그리지 않습니다.

실제 결과

이름

사는 곳

<form> 에는 action 과 method 라는 속성이 더 있습니다. "어디로 보낼지" 와 "어떻게 보낼지" 를 정하는 속성인데, 이 자료에서는 실제로 보내지 않으므로 일부러 비워 두었습니다. 개념05 에서 뜻만 짚어 봅니다.

✏️ 직접 해보기 1 — 위 상자 안 <form> 안에 <p>나이 <input type="text" name="userAge" /></p> 를 한 줄 더 넣어 보세요. 저장하고(Ctrl+S) 새로고침(F5) 하면 칸이 세 줄이 됩니다.

섹션 2 — 한 줄 입력칸 만들기: input

<input /> 은 닫는 태그가 없는 빈 태그입니다. type 속성이 이 칸이 어떤 종류인지를 정합니다.

실제 결과 — 세 칸 모두 똑같이 생겼습니다

제대로 쓴 것

type 을 안 쓴 것

type 에 오타를 낸 것

<input></input> 처럼 닫으려고 하지 마세요. 빈 태그라서 닫는 태그가 필요 없습니다. 브라우저는 그 닫는 태그를 조용히 버립니다. 이 자료에서는 빈 태그라는 것이 눈에 띄도록 <input /> 로 씁니다.

✏️ 직접 해보기 2 — 위 상자의 type="txet" 를 type="password" 로 고쳐 보세요. 새로고침한 뒤 그 칸에 글자를 쳐 보면 글자 대신 점이 찍힙니다. type 하나가 칸의 성격을 바꾼다는 것을 확인하는 것이 목적입니다.

섹션 3 — name: 값에 붙이는 이름표

name 이 없는 칸의 값은 아무 데도 가지 않습니다. 그런데 화면은 멀쩡합니다. 그래서 가장 알아채기 어려운 실수입니다.

실제 결과 — 이름표가 있는 칸과 없는 칸

이름표 있음

이름표 없음

name 은 보낼 때 쓰는 이름표입니다. 개념02 에서 id 라는 비슷하게 생긴 속성이 나오는데, 그것은 페이지 안에서 이 칸 하나를 가리키는 이름표라 쓰임새가 다릅니다. 두 개를 같이 쓰는 일이 아주 많으니 지금 구분해 두세요.

✏️ 직접 해보기 3 — 위 상자의 "이름표 없음" 칸에 name="userNick" 을 넣어 보세요. 새로고침해도 화면은 하나도 안 바뀝니다. 화면이 안 바뀌는 것을 눈으로 확인하는 것이 이 문제의 목적입니다.

섹션 4 — value: 칸에 미리 넣어 두는 값

value 는 페이지가 열리자마자 칸에 이미 들어가 있는 값입니다. 사용자가 지우거나 고칠 수 있습니다.

실제 결과

빈 칸

미리 채운 칸

✏️ 직접 해보기 4 — 위 상자의 value="김민준" 을 여러분 이름으로 바꿔 보세요. 새로고침하면 칸 안의 글자가 바뀝니다.

섹션 5 — placeholder 와 value 는 완전히 다릅니다

placeholder 는 값이 아니라 안내문입니다. 회색으로 보였다가 글자를 치는 순간 사라집니다.

실제 결과 — 세 칸을 비교해 보세요

value 만

placeholder 만

둘 다

✏️ 직접 해보기 5 — 위 상자의 셋째 칸에서 value="김민준" 만 지우고 새로고침해 보세요. 가려져 있던 회색 안내문이 나타납니다.

섹션 6 — 자주 하는 실수

폼의 실수는 화면이 멀쩡해서 더 위험합니다. 아래 다섯 가지는 전부 에러가 나지 않고, 눈으로도 거의 티가 나지 않습니다.

실수 1 — name 을 빠뜨림
<input type="text" value="김민준" />

칸은 잘 그려지고 글자도 잘 쳐집니다. 그런데 이 칸의 값만 쏙 빠진 채 나머지 값들이 보내집니다. 받는 쪽에서는 이름이 안 왔다고 나옵니다. "다 채웠는데 왜 안 들어갔지?" 의 1등 원인입니다.

이름표 없는 칸

이렇게 쓰세요
<input type="text" name="userName" value="김민준" />

이름표 있는 칸

실수 2 — placeholder 를 값이라고 생각함
<input type="text" name="city" placeholder="부산" />

회색으로 "부산" 이 보이니 값이 들어 있는 것처럼 착각합니다. 그 칸은 비어 있습니다. 사용자가 그냥 넘어가면 도시 값이 빈 채로 갑니다. 기본값을 진짜로 넣고 싶으면 value="부산" 을 써야 합니다.

실수 3 — input 을 닫는 태그로 닫음
<input type="text">여기 글자</input>

input 은 빈 태그라 안에 글자를 넣을 수 없습니다. "여기 글자" 는 칸 안이 아니라 칸 바깥에 그냥 떠 있는 글자가 되고, </input> 은 조용히 버려집니다. 에러는 없습니다.

여기 글자

실수 4 — 서로 다른 칸에 같은 name 을 붙임
<input name="user" /> <input name="user" />

이름표가 똑같은 상자 두 개를 보내는 셈입니다. 두 값이 다 가기는 하는데 받는 쪽에서 어느 것이 이름이고 어느 것이 도시인지 구분할 수 없습니다. 칸마다 다른 이름을 붙이세요. (다만 개념03 의 라디오 버튼만은 일부러 같은 name 을 씁니다. 그건 이유가 따로 있습니다)

실수 5 — 속성 값의 따옴표를 빠뜨림
<input type="text" placeholder=이름을 입력하세요 />

띄어쓰기가 있는 값에서 따옴표를 빼면, 브라우저는 첫 칸까지만 값으로 읽습니다. 안내문이 "이름을" 까지만 나오고 뒤의 "입력하세요" 는 입력하세요 라는 이름의 속성으로 잘못 읽힙니다. 역시 에러는 없습니다.

── 정리 ──

1. <form> 은 입력칸들을 한 묶음으로 만드는 상자입니다. 자기는 안 보입니다.

2. <input /> 은 빈 태그이고, type 이 칸의 종류를 정합니다.

3. type 을 안 쓰거나 오타를 내면 조용히 text 로 그려집니다.

4. name 은 값에 붙이는 이름표입니다. 없으면 그 값은 보내지지 않습니다.

5. value 는 미리 들어 있는 진짜 값, placeholder 는 회색 안내문입니다.

6. 폼의 실수는 화면이 멀쩡해서 안 보입니다. 코드를 눈으로 확인하는 습관이 필요합니다.
