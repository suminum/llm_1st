개념 06 — 브라우저에게 검사를 시키는 속성들

05단원 · 폼

이 파일에는 눌러도 페이지가 안 넘어가는 보내기 버튼이 있습니다. 칸을 비운 채로 누르면 검사에 걸려 제출이 막히기 때문입니다. 말풍선이 어떻게 뜨는지 직접 보세요. 반대로 칸을 다 채우고 누르면 그때는 진짜로 제출되어 페이지가 새로고침됩니다.

섹션 1 — required: 비어 있으면 제출을 막습니다

required 는 반드시 채워야 하는 칸이라는 표시입니다. 값이 없으면 제출 자체가 막힙니다.

실제 결과 — 빈 칸인 채로 "보내기" 를 눌러 보세요

이름 칸을 채우고 다시 누르면 이번에는 이메일 칸에서 막힙니다. 이메일 칸에 abc 라고만 쓰고 누르면 "이메일 주소에 '@'를 포함해 주세요. 'abc'에 '@'가 없습니다." 라는 다른 말풍선이 뜹니다. 뒷문장은 여러분이 친 글자에 따라 달라집니다. type="email" 이 값의 뜻을 알려 줬기 때문에 가능한 검사입니다.

✏️ 직접 해보기 1 — 세 번째 "별명" 칸에도 required 를 붙여 보세요. 새로고침하고 빈 칸인 채로 보내기를 누르면 세 칸을 차례로 다 채워야 넘어갑니다.

섹션 2 — maxlength 와 minlength: 막는 시점이 다릅니다

maxlength 는 치는 순간 막고, minlength 는 제출할 때 막습니다.

실제 결과 — 첫 칸에 여섯 글자를 쳐 보세요

✏️ 직접 해보기 2 — 첫 칸의 maxlength="5" 를 maxlength="2" 로 바꿔 보세요. 새로고침하면 세 번째 글자부터 안 쳐집니다.

섹션 3 — min, max, step: 숫자와 날짜의 범위

min 과 max 는 얼마부터 얼마까지, step 은 몇씩 건너뛰는지입니다.

실제 결과 — 화살표를 눌러 2씩 움직여 보세요

step 은 화살표로 움직일 때의 간격입니다. 자판으로 직접 4를 쳐 넣는 것은 막지 않습니다. 다만 보내기를 누르면 min="1" 에 step="2" 라서 1, 3, 5, 7, 9 만 맞는 값이므로 그때 말풍선이 뜹니다.

✏️ 직접 해보기 3 — 만족도 막대의 step="2" 를 step="5" 로 바꿔 보세요. 새로고침하고 손잡이를 끌면 0, 5, 10 세 자리에서만 멈춥니다.

섹션 4 — pattern: 정해진 모양만 받기

pattern 은 값이 어떤 모양이어야 하는지를 적는 속성입니다.

실제 결과 — 12 만 쓰고 보내기를 눌러 보세요

✏️ 직접 해보기 4 — 위 칸의 pattern="[0-9]{5}" 를 pattern="[0-9]{3}" 으로 바꿔 보세요. 새로고침하면 이번에는 세 자리를 써야 통과합니다.

섹션 5 — readonly 와 disabled: 비슷해 보여도 완전히 다릅니다

둘 다 "못 고치는 칸" 인데, 값이 보내지느냐가 결정적으로 다릅니다.

실제 결과 — 두 칸을 눌러 보고 색을 비교하세요

readonly 는 글자 칸에만 쓸 수 있습니다. 체크박스나 라디오, select 에는 효과가 없습니다. 그런 칸을 잠그려면 disabled 를 써야 하는데, 그러면 값도 같이 안 갑니다. 이럴 때 개념03 의 hidden 칸에 같은 값을 넣어 함께 보내는 방법을 씁니다.

✏️ 직접 해보기 5 — 두 번째 칸의 disabled 를 readonly 로 바꿔 보세요. 새로고침하면 회색이던 칸이 위 칸과 똑같은 흰 바탕 검은 글씨가 됩니다.

섹션 6 — autofocus 와 autocomplete

autofocus 는 열자마자 커서를 넣고, autocomplete 는 예전에 친 값 추천을 켜고 끕니다.

실제 결과 — 두 칸의 생김새를 비교하세요

✏️ 직접 해보기 6 — 위 첫 칸에 autofocus 를 붙이고 저장한 뒤 브라우저에서 F5 를 눌러 보세요. 페이지가 열리자마자 화면이 이 섹션까지 내려오고 첫 칸에 커서가 깜빡입니다. 확인했으면 반드시 지우세요. 안 지우면 이 파일을 열 때마다 화면이 여기로 떨어집니다.

섹션 7 — 브라우저 검사의 한계

브라우저 검사는 사용자를 도와주는 장치이지 값을 지켜 주는 장치가 아닙니다.

실제 결과 — maxlength 가 5인데 열두 글자가 들어 있습니다

위 칸에서 글자를 지우고 새로 쳐 보면 그때는 다섯 자까지만 들어갑니다. 사용자가 치는 값만 검사한다는 것이 눈으로 확인됩니다.

✏️ 직접 해보기 7 — 위 칸의 글자를 전부 지우고 여섯 글자를 쳐 보세요. 다섯 글자에서 멈춥니다. 같은 칸인데 결과가 다른 이유를 한 문장으로 적어 보세요.

섹션 8 — 자주 하는 실수

규칙 속성의 실수는 규칙이 있는 줄 알았는데 없는 종류입니다. 평소에는 잘 돌아가서 더 늦게 발견됩니다.

실수 1 — 고치지 못하게 하려고 disabled 를 씀
<input type="text" name="orderNo" value="A-2026-001" disabled />

화면에서는 목적을 이뤘습니다. 사용자가 못 고칩니다. 그런데 보내 보면 orderNo 라는 값이 아예 없습니다. disabled 인 칸은 없는 셈 치고 보내지 않기 때문입니다. 고치지 못하게 하면서 값도 보내려면 readonly 를 쓰세요.

이렇게 쓰세요
<input type="text" name="orderNo" value="A-2026-001" readonly />
실수 2 — required 를 붙였으니 빈 값은 절대 안 온다고 믿음
<input type="text" name="userName" required />

스페이스 한 칸만 쳐도 통과합니다. 브라우저는 "비어 있지 않다" 로 봅니다. 게다가 브라우저를 거치지 않고 보내면 검사 자체가 일어나지 않습니다. 서버에서 한 번 더 검사해야 하는 이유입니다.

실수 3 — 필수 표시를 화면에 안 적음
<label for="a">이름</label> <input id="a" type="text" required />

required 를 붙여도 화면에는 아무 표시도 안 납니다. 별표도, 빨간 테두리도 생기지 않습니다. 사용자는 다 채웠다고 생각하고 버튼을 눌렀다가 말풍선을 보고 당황합니다. 이름표에 "(필수)" 같은 글자를 직접 적어 주세요.

실수 4 — number 칸에 maxlength 를 씀
<input type="number" name="age" maxlength="3" />

아무 일도 안 일어납니다. 네 자리든 열 자리든 다 쳐집니다. maxlength 는 글자 수를 세는 속성이라 숫자 칸에는 효과가 없습니다. 숫자 칸의 범위는 min 과 max 로 정합니다.

실수 5 — pattern 만 쓰고 required 를 안 씀
<input type="text" name="zip" pattern="[0-9]{5}" />

우편번호를 아무것도 안 쓰고 보내면 그냥 통과합니다. pattern 은 값이 있을 때만 모양을 봅니다. 빈 값은 검사하지 않습니다. "비어도 안 된다" 까지 시키려면 required 를 같이 쓰세요.

── 정리 ──

1. required 는 빈 칸이면 제출을 막습니다. 화면에는 표시가 안 납니다.

2. maxlength 는 치는 순간 막고, minlength 는 보낼 때 막습니다.

3. min, max, step 은 숫자와 날짜의 범위를 정합니다.

4. pattern 은 값의 모양을 정합니다. 빈 값은 검사하지 않습니다.

5. readonly 는 값이 보내지고, disabled 는 안 보내집니다.

6. autofocus 는 한 페이지에 하나만, autocomplete 는 부탁일 뿐입니다.

7. 브라우저 검사는 사용자를 돕는 장치입니다. 서버에서 반드시 다시 검사합니다.
