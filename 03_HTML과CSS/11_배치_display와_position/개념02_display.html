개념 02 — display

11단원 · 배치 (display와 position)

02단원에서 남겨 둔 블록·인라인 이야기를 여기서 끝냅니다. 특히 섹션 2, 섹션 3 은 초보자가 가장 많이 걸려 넘어지는 자리입니다. "분명히 width 를 줬는데 안 바뀐다" 의 정체가 여기 있습니다.

섹션 1 — 태그의 기본 성질을 맞바꾸기

태그는 저마다 기본 display 값을 갖고 태어납니다. 그 값을 CSS 로 덮어쓸 수 있습니다.

기본값 그대로

저는 span 입니다 저도 span 입니다
저는 div 입니다
저도 div 입니다

display 로 성질을 맞바꾼 결과

저는 span 인데 block 저도 span 인데 block
저는 div 인데 inline
저도 div 인데 inline

✏️ 직접 해보기 1 — <style> 의 .div-as-inline 을 display: block; 으로 바꿔 보세요. 아래 div 두 개가 다시 위아래로 쌓입니다. 확인했으면 inline 으로 되돌려 놓으세요.

섹션 2 — inline 에는 width·height 가 안 먹습니다

아래 두 조각에는 똑같이 width: 300px; height: 70px; 를 줬습니다. 그런데 하나만 커집니다.

display: inline 인 조각

display: inline 입니다

display: inline-block 인 조각

display: inline-block 입니다

같은 이유로 인라인 요소에는 height 도 안 먹습니다. 인라인 조각의 세로 크기는 글자 크기와 line-height(09단원) 가 정합니다.

✏️ 직접 해보기 2 — .size-inline 의 width 를 900px 로 바꿔 보세요. 그래도 아무 일도 안 일어납니다. 값이 문제가 아니라 display 가 문제라는 것을 확인하는 것이 목적입니다.

섹션 3 — inline 에는 위아래 margin 도 안 먹습니다

margin: 30px 40px 을 똑같이 줬는데, 인라인에서는 좌우 40px 만 먹고 위아래 30px 은 무시됩니다.

가운데 조각이 display: inline 인 경우

윗줄입니다
앞가운데뒤
아랫줄입니다

가운데 조각이 display: inline-block 인 경우

윗줄입니다
앞가운데뒤
아랫줄입니다

재미있는 것은, 개발자 도구로 첫 번째 노란 조각을 찍어 보면 margin-top 이 30px 이라고 그대로 적혀 있다는 점입니다. 값은 들어가 있는데 화면 계산에서만 빠집니다. 이 파일 맨 아래 자동 검사에서도 그 사실을 그대로 확인합니다.

✏️ 직접 해보기 3 — .mg-inline 의 margin 을 80px 40px 으로 바꿔 보세요. 위아래는 여전히 꿈쩍도 안 합니다. 확인했으면 30px 40px 으로 되돌려 놓으세요.

섹션 4 — inline-block 이 그 문제를 풉니다

inline-block 은 바깥에서는 인라인, 안에서는 블록입니다. 옆으로는 붙으면서 크기는 내 마음대로 정합니다.

카드 안의 글자가 가운데로 온 것은 09단원에서 배운 text-align: center 때문입니다. display 가 한 일이 아닙니다. 두 가지를 섞어서 기억하지 마세요.

✏️ 직접 해보기 4 — .card 의 display 를 block 으로 바꿔 보세요. 카드 세 장이 위아래로 쌓입니다. 확인했으면 inline-block 으로 되돌려 놓으세요.

섹션 5 — 숨기는 두 가지 방법

둘 다 눈에서 사라집니다. 차이는 딱 하나, 자리를 차지하느냐입니다.

display: none 으로 B 를 숨긴 결과

A 줄입니다
B 줄입니다 (display: none)
C 줄입니다

visibility: hidden 으로 B 를 숨긴 결과

A 줄입니다
B 줄입니다 (visibility: hidden)
C 줄입니다

visibility 는 display 와 아주 헷갈리는 이름이지만 전혀 다른 속성입니다. display: hidden 이나 visibility: none 같은 값은 없습니다. 그렇게 쓰면 그 줄은 조용히 무시됩니다.

✏️ 직접 해보기 5 — .none-box 를 visibility: hidden; 으로 바꿔 보세요. 두 데모가 똑같은 모양이 됩니다. 확인했으면 display: none; 으로 되돌리세요.

섹션 6 — 자주 하는 실수

여기 있는 것들은 전부 에러가 나지 않습니다. "왜 안 되지?" 하면서 오래 헤매게 되는 종류입니다.

실수 1 — 인라인 요소에 width 를 줌
<span class="btn">보내기</span> .btn { width: 200px; background: #2d6cdf; }

아무 일도 안 일어납니다. 글자 길이만큼만 파랗게 칠해집니다. 버튼처럼 폭이 있는 것을 만들려면 display: inline-block 을 먼저 붙여야 합니다. 이 단원에서 가장 자주 나는 실수입니다.

이렇게 하세요
.btn { display: inline-block; width: 200px; background: #2d6cdf; }
실수 2 — 인라인 요소에 위아래 margin 을 줌
.tag { margin-top: 40px; } /* .tag 는 span 입니다 */

위아래 간격이 하나도 안 벌어집니다. 그런데 좌우 margin 은 잘 먹습니다. 그래서 "margin 은 되는데 왜 위만 안 되지?" 하고 더 헷갈립니다. 세로로 밀고 싶으면 display 를 inline-block 이나 block 으로 바꾸세요.

실수 3 — display: none 이면 빈칸은 남을 거라고 생각함
.msg { display: none; }

자리까지 통째로 사라집니다. 아래에 있던 요소들이 전부 위로 올라옵니다. 그래서 "숨겼더니 아래 내용이 갑자기 들썩였다" 는 일이 생깁니다. 자리를 남기고 싶으면 visibility: hidden 을 쓰세요.

실수 4 — inline-block 사이의 틈을 margin 탓으로 오해함
.card { display: inline-block; margin: 0; }

margin: 0 을 줬는데도 카드 사이에 6px 쯤 틈이 남습니다. 그 틈은 margin 이 아니라 코드에서 카드 사이에 친 줄바꿈(공백)입니다. 인라인이라 글자 취급을 받아서 단어 사이 공백이 낀 것입니다. margin 을 아무리 0 으로 만들어도 사라지지 않습니다.

실수 5 — 값 이름을 잘못 씀
.box { display: inlineblock; } .box { display: hidden; }

둘 다 그 줄 전체가 조용히 무시됩니다. 요소는 원래 성질 그대로 남습니다. inline-block 은 가운데 붙임표가 있어야 하고, 숨기는 값은 display: none 입니다. hidden 은 visibility 의 값입니다.

── 정리 ──

1. display 는 태그가 타고난 블록·인라인 성질을 바꾸는 속성입니다.

2. block 은 한 줄을 통째로, inline 은 글자처럼 옆으로 붙습니다.

3. 인라인에는 width·height·위아래 margin 이 안 먹습니다.

4. inline-block 은 옆에 붙으면서 크기도 정할 수 있는 절충안입니다.

5. display: none 은 자리까지 없애고, visibility: hidden 은 자리를 남깁니다.

6. 안 먹는 CSS 는 에러가 아니라 침묵입니다. 화면을 눈으로 확인하세요.
