개념 01 — 문서 흐름

11단원 · 배치 (display와 position)

이 파일은 배치를 바꾸는 방법을 배우지 않습니다. 바꾸기 전에 지금 이미 무슨 규칙으로 놓이고 있는지를 봅니다. 아래 상자들을 보면서 "왜 이건 세로로 쌓이고, 저건 옆으로 붙지?" 를 계속 물어 보세요.

같은 흐름 안에서도 요소는 두 부류로 나뉩니다. 한 줄을 통째로 쓰는 것과 글자처럼 옆에 붙는 것입니다.

섹션 3 — 흐름은 코드에 쓴 순서를 그대로 따릅니다

흐름의 순서는 여러분이 코드를 쓴 순서입니다. 다만 코드에서 줄을 바꾼 것은 화면의 줄바꿈이 아닙니다.

섹션 4 — 이 단원의 지도: 흐름을 바꾸는 손잡이 세 개

11단원에서 배우는 것은 결국 흐름을 바꾸는 손잡이 세 개입니다. 지금 전부 이해할 필요는 없습니다. 어디로 가는지만 봐 두세요.

11단원에서 배울 것

  • display — 한 줄 통째로 쓸지, 글자처럼 옆에 붙을지 (개념02)
  • position — 흐름에서 꺼내 원하는 자리에 놓기 (개념03, 개념04)
  • z-index — 겹쳤을 때 누가 위로 올라올지 (개념05)

✏️ 직접 해보기 4 — 위 목록에 <li>float — 글 옆에 흘리기 (개념05)</li> 를 한 줄 더 넣어 보세요. 목록이 네 줄이 됩니다.

섹션 5 — 자주 하는 실수

CSS 도 HTML 과 똑같습니다. 틀려도 에러가 나지 않습니다. 그 줄이 조용히 무시될 뿐입니다. 그래서 "아무 일도 안 일어난다" 가 가장 흔한 증상입니다.

실수 1 — 스페이스를 여러 번 쳐서 간격을 만들려 함
<span>왼쪽</span> <span>오른쪽</span>

한 칸만 벌어집니다. 연속된 공백은 한 칸으로 합쳐지기 때문입니다. 간격은 10단원에서 배운 margin 이나 padding 으로 만듭니다.

왼쪽 오른쪽
이렇게 하세요
.gap { margin-right: 40px; }
실수 2 — br 을 여러 개 써서 세로 간격을 만듦
<p>위</p> <br /><br /><br /> <p>아래</p>

화면은 일단 벌어집니다. 그래서 더 나쁩니다. 글자 크기를 바꾸면 간격도 같이 바뀌고, 나중에 margin 으로 고치려 할 때 어디가 진짜 간격인지 못 찾습니다. 세로 간격은 margin 하나로만 만드세요.

실수 3 — 블록 두 개를 붙여 쓰면 옆에 놓일 거라고 생각함
<div>왼쪽 칸</div><div>오른쪽 칸</div>

코드에서 붙여 써도 화면에서는 위아래로 쌓입니다. 블록은 한 줄을 통째로 차지한다는 규칙이 먼저이기 때문입니다. 가로로 놓으려면 개념02 의 inline-block 이나 12단원의 flex 가 필요합니다.

왼쪽 칸
오른쪽 칸
실수 4 — 처음부터 좌표로 전부 배치하려 함
.a { position: absolute; top: 100px; left: 0; } .b { position: absolute; top: 160px; left: 0; } .c { position: absolute; top: 220px; left: 0; }

당장은 맞아 보입니다. 그런데 .a 의 글자가 한 줄 늘어나는 순간 세 개가 서로 겹칩니다. 흐름에서 꺼낸 요소는 서로를 밀어내지 않기 때문입니다. 흐름에 맡길 수 있는 것은 끝까지 흐름에 맡기세요.

실수 5 — 코드에서 엔터를 쳤으니 화면도 줄이 바뀔 거라 생각함
<span>첫째</span> <span>둘째</span>

화면에서는 한 줄로 이어집니다. 엔터는 공백 한 칸이 됩니다. 섹션 3 에서 이미 눈으로 확인했습니다. 진짜 줄바꿈은 <br /> 이거나 블록 요소입니다.

── 정리 ──

1. 문서 흐름은 위치를 안 정해 줬을 때 브라우저가 요소를 놓는 기본 순서입니다.

2. 블록은 한 줄을 통째로 쓰고 세로로 쌓입니다. 글자 길이와 상관없이 폭을 채웁니다.

3. 인라인은 옆으로 이어지다가 줄이 모자라면 다음 줄로 내려갑니다.

4. 코드의 줄바꿈과 연속 공백은 공백 한 칸으로 합쳐집니다.

5. 이 단원의 손잡이는 display, position, z-index 셋입니다.

6. 될 수 있으면 흐름에 맡기고, 흐름으로 안 되는 것만 흐름에서 꺼냅니다.
