개념 03 — 주축 정렬 (justify-content 와 gap)

12단원 · Flexbox

이 파일의 무대(옅은 파란 칸)는 모두 안쪽 폭 600px, 상자는 모두 폭 100px 입니다. 그래서 남는 공간은 항상 300px 입니다. 이 300px 이 어디로 가는지만 보면 여섯 가지 값이 한눈에 구분됩니다.

이 파일에 나오는 "왼쪽 좌표" 는 브라우저 창을 1280px 로 놓고 잰 값입니다. 본문이 가운데 정렬이라 창 폭이 다르면 숫자가 통째로 좌우로 밀립니다. 숫자 자체를 외우지 말고, 상자들 사이의 차이(간격·나뉜 몫)를 보세요. 그 차이는 창 폭과 상관없이 늘 같습니다.

섹션 6 — 자주 하는 실수

전부 에러 없이 조용히 넘어가는 실수들입니다.

실수 1 — 상자 자신에게 justify-content 를 씀
.tile { justify-content: center; } /* 아이템에 썼습니다 */

상자는 꼼짝도 하지 않습니다. justify-content 는 컨테이너가 자기 아이템들을 어디에 모을지 정하는 속성입니다. "가운데로 가고 싶다" 는 상자의 소원은 CSS 에서 표현할 수 없습니다.

1
2
이렇게 쓰세요
.jc-item-stage { justify-content: center; } /* 컨테이너에 */
실수 2 — 상자 안의 글자까지 가운데로 갈 거라고 생각함
.jc-text-stage { justify-content: center; }

상자는 가운데로 모이지만 상자 안 글자는 왼쪽에 그대로 있습니다. justify-content 가 옮기는 것은 아이템이지 글자가 아닙니다. 글자를 가운데로 보내려면 09단원에서 배운 text-align: center 를 상자에 써야 합니다.

실수 3 — 값 이름을 left, right 로 지어냄
.jc-typo-stage { justify-content: right-end; }

그런 값은 없어서 그 한 줄이 통째로 버려집니다. 기본값 flex-start 로 남아 상자가 왼쪽에 붙습니다. 오른쪽으로 보내는 값의 이름은 flex-end 입니다.

1
2
실수 4 — 남는 공간이 없는데 값만 계속 바꿔 봄
/* 아이템이 무대를 꽉 채운 상태에서 값만 바꾸는 경우 */

여섯 가지 값을 다 넣어 봐도 화면이 하나도 안 바뀝니다. 나눠 줄 공간이 0 이기 때문입니다. 이럴 때는 정렬 값이 아니라 아이템 폭이나 무대 폭을 봐야 합니다. 개념05 에서 배울 flex: 1 이 붙어 있어도 같은 일이 벌어집니다.

실수 5 — margin 으로 간격을 만들고 가운데가 안 맞는다고 함
.tile { margin-right: 30px; } /* 마지막 상자에도 붙습니다 */

섹션 5 의 첫 무대가 이것입니다. 15px 이 어긋납니다. 정렬은 분명히 center 인데 눈으로는 왼쪽으로 치우쳐 보이니 정렬 값을 계속 바꿔 보면서 시간을 씁니다. 범인은 마지막 상자 오른쪽의 30px 입니다. gap 으로 바꾸면 사라집니다.

── 정리 ──

1. justify-content 는 주축에서 남는 공간을 어떻게 쓸지 정합니다.

2. 값 여섯 개: flex-start · center · flex-end · space-between · space-around · space-evenly.

3. between 은 가장자리 0, around 는 가장자리가 사이의 절반, evenly 는 전부 같습니다.

4. gap 은 아이템 사이에만 간격을 넣습니다. 가장자리에는 안 붙습니다.

5. gap 은 가로·세로 모두에 적용되고, 마지막 여백 예외 처리가 필요 없습니다.

6. 둘 다 컨테이너에 쓰는 속성입니다. 아이템에 쓰면 조용히 무시됩니다.
