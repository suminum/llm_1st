05단원 연습문제 정답 — 폼

05단원 · 폼

상자 안에 있는 것이 답의 실행 결과입니다. 코드는 VS Code 에서 이 파일의 소스를 보세요. 결과가 같으면 코드가 조금 달라도 맞은 것입니다. 특히 이름표를 연결하는 방법은 두 가지 다 정답입니다.

문제 1 — 정답

이름

form 은 아무것도 안 그립니다. 칸들을 한 묶음으로 만드는 상자일 뿐입니다. name 이 없으면 사용자가 값을 채워도 그 값은 어디에도 보내지지 않습니다. 화면은 똑같아서 알아챌 수 없으니 습관처럼 붙이세요.

문제 2 — 정답

이메일

placeholder 는 값이 아니라 안내문입니다. 보내지지 않습니다. value 를 썼다면 검은 글씨가 들어가고 사용자가 지워야 없어집니다. 둘을 같이 쓰면 값이 안내문을 가려 안내문이 아예 안 보입니다.

문제 3 — 정답

사는 곳

value 는 진짜 값입니다. 사용자가 아무것도 안 해도 이 값이 보내집니다. 회원 정보 수정 화면처럼 지금 저장된 값을 보여 줘야 할 때 씁니다.

문제 4 — 정답 ("나이" 글자를 눌러 보세요)

for 값과 id 값이 글자 하나까지 같아야 연결됩니다. 대소문자도 구별합니다. 값이 어긋나면 에러 없이 그냥 안 눌립니다. 여기서는 id 와 name 이 둘 다 userAge 인데, 값만 같을 뿐 id 는 연결용, name 은 보낼 때 쓰는 이름표입니다.

문제 5 — 정답 (글자 아무 데나 눌러 보세요)

감싸면 for 와 id 를 안 써도 브라우저가 짝을 알아냅니다. 체크박스는 누를 곳이 13픽셀짜리 작은 네모라 연결이 특히 중요합니다. 연결하면 글자까지 누를 곳이 되어 훨씬 편해집니다.

문제 6 — 정답

배송 정보

legend 는 fieldset 의 첫 자식으로 씁니다. fieldset 밖에 쓰면 테두리와 아무 관계 없는 그냥 글자가 되어 상자 위에 따로 놓입니다. 05단원에서 여러 칸을 묶을 때 쓸 수 있는 상자입니다.

문제 7 — 정답 (네 칸에 모두 값을 넣어 보세요)

type 값 하나로 생김새와 넣는 방법이 한꺼번에 바뀝니다. type 에 오타를 내면 에러 없이 조용히 text 로 그려집니다. 네 칸이 전부 똑같이 생겼다면 철자를 의심하세요.

문제 8 — 정답 (세 개를 다 켜 보세요)

체크박스는 name 이 같아도 서로 끄지 않습니다. 각각 따로 노는 스위치입니다. value 를 안 쓰면 켜졌을 때 on 이라는 값이 가서 무엇을 골랐는지 알 수 없게 됩니다. 꼭 적으세요.

문제 9 — 정답 (세 개를 차례로 눌러 보세요)

라디오 버튼을 한 무리로 묶는 것은 위치가 아니라 name 입니다. 세 개의 name 이 모두 pay 라서 하나만 켜집니다. 하나라도 다르게 쓰면 그 버튼은 혼자 노는 스위치가 되어 따로 켜집니다.

문제 10 — 정답 (상자를 눌러 펼쳐 보세요)

option 의 value 가 보내는 값이고, 태그 사이의 글자가 화면에 보이는 글자입니다. 나눠 두면 나중에 화면 글자를 바꿔도 보내는 값은 그대로라 받는 쪽을 안 고쳐도 됩니다.

문제 11 — 정답 (Ctrl+A 를 눌러 보세요)

여는 태그와 닫는 태그를 딱 붙여 써야 진짜 빈 칸이 됩니다. 보기 좋게 줄을 바꾸면 그 줄바꿈과 들여쓰기 공백이 그대로 값이 되어 버립니다. 그러면 사용자가 아무것도 안 써도 빈 값이 아니게 됩니다.

문제 12 — 정답 (글자를 치고 버튼을 눌러 보세요)

type 을 안 쓰면 기본이 submit 이라 누르는 순간 제출됩니다. 제출과 상관없는 버튼에는 반드시 type="button" 을 쓰세요. 버튼을 만들 때 type 부터 쓰는 습관을 들이면 이 사고가 사라집니다.

문제 13 — 정답 ("지역" 글자를 누른 뒤 키보드 아래 화살표를 눌러 보세요)

optgroup 의 label 속성에 쓴 글자가 묶음 제목이 됩니다. 제목은 항목이 아니라서 고를 수 없습니다.

label 로 감싸면 select 도 이름표와 연결됩니다. 다만 글자를 눌러도 목록이 저절로 펼쳐지지는 않습니다. 체크박스는 글자를 누르면 바로 켜지지만, 목록 상자는 포커스만 옮겨 갑니다. 크롬은 목록 상자를 직접 눌렀을 때만 목록을 펼치기 때문입니다. 연결이 되었는지 확인하려면 글자를 누른 뒤 키보드 아래 화살표를 눌러 보세요. 고른 항목이 바뀌면 포커스가 넘어간 것입니다. 연결해 두면 화면 낭독기도 이 목록의 이름이 "지역" 이라고 읽어 줍니다.

문제 14 — 정답 (이름을 비운 채로 보내기를 눌러 보세요)

readonly 는 못 고치게 하면서 값은 그대로 보냅니다. disabled 를 쓰면 글씨가 회색으로 흐려지고 그 칸의 값이 아예 보내지지 않습니다. 여기서 자주 실수합니다. maxlength 는 치는 순간 막고, required 는 보낼 때 막습니다.

문제 15 — 정답 (값을 바꾼 뒤 되돌리기를 눌러 보세요)

기본 정보

추가 정보

성별

관심 분야

fieldset 으로 묶으면 긴 폼이 한눈에 들어옵니다. "성별" 과 "관심 분야" 처럼 여러 칸 전체의 제목은 label 이 아니라 그냥 문단으로 적습니다. label 은 칸 하나에 붙이는 이름표이기 때문입니다. type="reset" 은 비우는 것이 아니라 처음 상태로 되돌립니다.

문제 16 — 정답 (세 가지를 모두 눌러서 확인하세요)

결제 수단

세 가지 모두 에러가 나지 않는 실수였습니다. 화면만 봐서는 고치기 전과 후가 똑같이 생겼습니다. HTML 은 틀려도 조용하기 때문에, 만든 사람이 직접 눌러 보고 확인해야 합니다.

── 05단원에서 꼭 기억할 것 ──

1. name 이 없으면 값이 안 갑니다. 화면은 멀쩡합니다.

2. label 을 연결하면 글자를 눌러도 칸이 켜집니다. 이것이 확인 방법입니다.

3. 라디오 버튼은 name 이 같아야 하나만 골라집니다.

4. textarea 는 태그 사이 공백까지 값이 됩니다. 딱 붙여 쓰세요.

5. 버튼에 type 을 안 쓰면 기본이 submit 입니다.

6. readonly 는 값이 가고 disabled 는 값이 안 갑니다.

7. 브라우저 검사는 도움일 뿐입니다. 서버에서 반드시 다시 검사합니다.
