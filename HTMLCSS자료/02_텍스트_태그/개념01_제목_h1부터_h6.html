개념 01 — 제목, h1 부터 h6 까지

02단원 · 텍스트 태그

이 파일은 제목 태그 여섯 개를 다룹니다. 크기가 어떻게 달라지는지 보는 것이 목적이 아니라, 제목이 글의 목차를 만든다는 것을 이해하는 것이 목적입니다. 화면과 VS Code 를 계속 번갈아 보세요.

섹션 1 — 제목 태그는 여섯 개입니다

h1 부터 h6 까지 여섯 개가 전부입니다. h7 은 없습니다.

실제 결과

h1 제목입니다

h2 제목입니다

h3 제목입니다

h4 제목입니다

h5 제목입니다
h6 제목입니다

제목 태그는 한 줄을 통째로 차지합니다. 옆에 다른 글자를 붙일 수 없고, 다음 내용은 반드시 아랫줄로 내려갑니다. 이런 성질을 가진 요소를 블록 요소라고 부릅니다. 블록 요소는 개념04 에서 제대로 다룹니다.

✏️ 직접 해보기 1 — 위 상자의 <h3>h3 제목입니다</h3> 안의 글자를 여러분 이름으로 바꿔 보세요. 저장하고(Ctrl+S) 브라우저에서 새로고침(F5) 하면 바뀝니다.

섹션 2 — 제목은 글의 목차를 만듭니다

제목 태그의 진짜 일은 꾸미기가 아니라 글을 덩어리로 나누는 것입니다.

실제 결과

김치찌개 만들기

재료 준비

돼지고기와 김치를 준비합니다.

만드는 순서

냄비에 김치를 볶습니다.

✏️ 직접 해보기 2 — 위 상자 맨 아래에 <h3>보관 방법</h3> 을 한 줄 넣어 보세요. "만드는 순서" 와 똑같은 크기로 세 번째 소제목이 생깁니다.

섹션 3 — h1 은 한 페이지에 하나만 씁니다

h1 은 "이 페이지 전체가 무엇에 대한 글인가" 를 적는 자리입니다. 그런 문장은 페이지마다 하나뿐입니다.

실제 결과 — 한 페이지 안의 제목 구조

우리 동네 빵집

아침 7시에 문을 엽니다.

인기 있는 빵

소보로빵과 단팥빵이 잘 나갑니다.

찾아오는 길

시장 정문 바로 앞입니다.

잘못된 예
<h1>우리 동네 빵집</h1> <h1>인기 있는 빵</h1> <h1>찾아오는 길</h1>

셋 다 h1 이라 어느 것이 페이지의 주제인지 알 수 없습니다. 화면에는 큰 글씨 세 줄이 멀쩡하게 나옵니다. 보기에는 아무 문제가 없어서 더 알아채기 어렵습니다.

이렇게 쓰세요
<h1>우리 동네 빵집</h1> <h2>인기 있는 빵</h2> <h2>찾아오는 길</h2>

✏️ 직접 해보기 3 — VS Code 에서 Ctrl+F 를 누르고 <h1 을 찾아보세요. 몇 군데가 찾아지는지 세고, 그중 진짜로 화면에 그려지는 h1 은 몇 개인지도 세어 보세요.

섹션 4 — 단계를 건너뛰지 마세요

h2 다음에 갑자기 h4 를 쓰면 안 됩니다. 한 단계씩 내려갑니다.

단계를 건너뛴 예 (h2 다음에 h4)

김치찌개 만들기

재료 준비

돼지고기와 김치를 준비합니다.

제대로 쓴 예 (h2 다음에 h3)

김치찌개 만들기

재료 준비

돼지고기와 김치를 준비합니다.

올라올 때는 건너뛰어도 됩니다. h3 으로 작은 덩어리를 끝내고 다음 h2 로 올라가는 것은 정상입니다. 내려갈 때만 한 단계씩 내려가면 됩니다.

✏️ 직접 해보기 4 — 첫 번째 상자의 <h4> 와 </h4> 를 <h3> 와 </h3> 로 고쳐 보세요. 두 상자가 똑같아집니다.

섹션 5 — 글씨를 크게 하려고 h1 을 쓰면 안 되는 이유

이 파일에서 가장 중요한 섹션입니다. 제목 태그는 크기 조절 도구가 아닙니다.

실제 결과 — 크기를 재 보면

h4 로 쓴 제목

그냥 p 로 쓴 문단

h6 로 쓴 제목
잘못된 예
<h1>오늘의 메뉴는 김치찌개입니다</h1>

글씨를 크게 하려고 h1 을 썼습니다. 화면에서는 실제로 커집니다. 그래서 잘못된 줄 모르고 넘어갑니다. 하지만 이 페이지의 주제가 "오늘의 메뉴는 김치찌개입니다" 로 바뀌어 버렸습니다.

이렇게 쓰세요
<p>오늘의 메뉴는 김치찌개입니다</p>

본문이니까 p 로 씁니다. 크게 만들고 싶으면 09단원에서 CSS 로 크기를 줍니다. 태그는 뜻으로 고르고, 모양은 CSS 로 바꿉니다. 이 문장이 이 자료 전체를 관통하는 원칙입니다.

✏️ 직접 해보기 5 — 위 상자에서 <h6 id="tiny-h6"> 를 <h2 id="tiny-h6"> 로, </h6> 를 </h2> 로 바꿔 보세요. 같은 글자가 얼마나 커지는지 확인한 뒤 원래대로 되돌리세요.

섹션 6 — 자주 하는 실수

01단원에서 배운 것을 다시 기억하세요. 아래 실수들은 전부 에러가 나지 않습니다. 화면이 조용히 이상해질 뿐입니다.

실수 1 — 크기가 마음에 든다는 이유로 단계를 고름
<h2>김치찌개 만들기</h2> <h5>재료 준비</h5>

h3 은 커 보이고 h5 는 딱 좋아 보여서 h5 를 골랐습니다. 화면은 원하는 대로 나옵니다. 그래서 아무도 안 알려 줍니다. 대신 목차에 h3, h4 두 층이 비어 있는 상태가 됩니다.

실수 2 — h7 을 씀
<h7>더 작은 제목</h7>

h7 이라는 태그는 없습니다. 브라우저는 모르는 태그를 없는 셈 치고 안의 글자만 그립니다. 굵어지지도 커지지도 않고 그냥 보통 글자로 나옵니다. 아래 상자가 실제 결과입니다.

h7 을 쓴 실제 결과

더 작은 제목
실수 3 — 여는 쪽과 닫는 쪽의 숫자가 다름
<h2>우리 동네 빵집</h3>

h2 로 열고 h3 으로 닫았습니다. 브라우저는 짝이 안 맞는 </h3> 를 그냥 버리고 h2 를 알아서 닫습니다. 결과는 h2 로 보이지만, 코드를 나중에 읽는 사람은 h3 인 줄 알고 헷갈립니다.

실수 4 — 제목 안에 문단을 넣음
<h2>빵집 소개 <p>아침 7시에 엽니다</p> </h2>

제목은 한 줄짜리 이름표입니다. 그 안에 문단이 들어갈 자리가 없습니다. 그런데 브라우저는 이것도 에러로 보지 않고 p 를 h2 안에 그대로 넣어 둡니다. 그러면 안쪽 p 가 h2 의 큰 글씨와 굵기를 그대로 물려받습니다. 본문으로 쓴 줄이 제목처럼 크고 굵게 나오는 것입니다. 아래가 실제 결과입니다.

제목 안에 문단을 넣은 실제 결과

빵집 소개

아침 7시에 엽니다

이게 원래 본문 크기입니다

실수 5 — 본문 없이 제목만 이어 씀
<h2>메뉴</h2> <h3>아메리카노</h3> <h3>카페라떼</h3> <h3>녹차라떼</h3>

제목은 "이 아래에 내용이 있다" 는 표시입니다. 내용이 없으면 표시할 것이 없습니다. 메뉴 이름을 늘어놓는 것은 목록이 할 일이고, 목록 태그는 03단원에서 배웁니다. 지금은 p 로 쓰면 됩니다.

── 정리 ──

1. 제목 태그는 h1 부터 h6 까지 여섯 개입니다. h7 은 없습니다.

2. 숫자는 크기가 아니라 단계입니다. 작을수록 큰 단계입니다.

3. h1 은 페이지 전체의 제목이므로 한 페이지에 하나만 씁니다.

4. 내려갈 때는 한 단계씩 내려갑니다. h2 다음에 h4 는 쓰지 않습니다.

5. h4 는 p 와 크기가 같고 h6 은 더 작습니다. 제목 태그는 크기 도구가 아닙니다.

6. 크기를 바꾸고 싶으면 09단원의 CSS 로 바꿉니다. 태그는 뜻으로 고르고, 모양은 CSS 로 바꿉니다.
