# DB자료 제작 지침 (집필자용)

이 문서는 **자료를 만드는 사람**을 위한 것입니다. 학생에게 배포하지 않습니다.

## 0. 이 자료가 무엇인가

**PART 5 — 데이터베이스와 SQL.** PostgreSQL 중심, MySQL 비교 포함.

- 대상: 자바스크립트 기초는 아는 사람. **DB는 처음.**
- 독립 교재입니다. 다른 자료를 안 봐도 완결됩니다.
- 분량: 10단원 / 약 66교시 / 파일당 250~500줄

## 1. 절대 규칙 — 이걸 어기면 자료가 망가집니다

### ① 모든 출력은 실제로 실행해서 얻은 값이어야 합니다

감으로 적으면 안 됩니다. **반드시 실행하고, 나온 값을 그대로 붙이세요.**

```bash
node 개념03_....js                       # 먼저 실행해서 눈으로 보고
node _검증도구/출력검증.cjs 03_....       # 기계로 대조해서 0불일치 확인
```

**0불일치가 아니면 그 파일은 완성이 아닙니다.**

### ② 측정값은 여러 번 재고 중앙값을 쓰세요

한 번 재고 결론 내리면 안 됩니다. 실제로 이 자료를 만들며 두 번 뒤집혔습니다.

- 메모리를 `heapUsed` 로 그냥 쟀더니 **0 MB** 가 나왔습니다 → 깨끗한 자식 프로세스에서 재야 합니다
- 파일 vs DB 검색을 쟀더니 **메모리 filter 가 더 빨랐습니다** → 이미 올려둔 상태와 비교하면 안 됩니다

측정값을 적을 때는 판정을 따로 찍으세요. 값은 기계마다 다릅니다.

```js
console.log(`색인 있음: ${있음ms.toFixed(1)} ms`);
// 출력?: 색인 있음: 1.2 ms          ← 값은 안 봄, 줄만 확인

console.log("색인이 더 빠른가:", 있음ms < 없음ms);
// 출력: 색인이 더 빠른가: true      ← 이게 진짜 검사
```

### ③ 학생이 틀릴 곳을 미리 보여주세요

"이렇게 하세요" 만 있으면 안 됩니다. **틀린 것을 실제로 돌려서** 무슨 일이 나는지 보여주세요.
SQL 인젝션은 진짜로 뚫고, 데드락은 진짜로 만들고, N+1 은 진짜로 느리게 만드세요.

## 2. 선언 문법 (검증도구가 읽습니다)

```js
console.log(1 + 2);
// 출력: 3
```

- `// 출력:` 은 **반드시 다음 줄에 단독으로**. 코드 뒤에 붙이면 수집 안 됩니다
- 여러 줄이 찍히면 `// 출력:` 도 그 줄 수만큼
- 기계마다 다른 값(시간·메모리·UUID·현재시각)은 `// 출력?:`
- 일부러 틀린 코드를 보여줄 때는 `// 검증무시:` 를 줄 끝이나 윗줄에

**주의: `console.log` 로 여러 인자를 넘기면 공백 하나로 이어집니다.**
`padEnd` 로 칸 맞추지 마세요. 한글은 터미널에서 2칸인데 `padEnd` 는 1칸으로 셉니다.
표는 `·` 나 `—` 로 잇거나, 주석으로 그리세요.

### ★★ `console.log` 의 `%` 서식 (실측으로 정정한 것입니다)

**인자가 1개면 Node 는 서식 해석을 아예 안 합니다.** 2개 이상일 때만 합니다.

```js
console.log("44%% 줄었습니다");        // → 44%% 줄었습니다   ← 안 접힙니다!
console.log("44%% 줄었습니다", "");    // → 44% 줄었습니다    ← 접힙니다
console.log("95%s 입니다");            // → 95%s 입니다
console.log("95%s 입니다", "");        // → 95 입니다         ← %s 가 통째로 치환됩니다
console.log("44% 줄었습니다", "");     // → 44% 줄었습니다    ← 뒤가 서식문자가 아니면 그대로
```

- 인자 1개면 `%` 를 **그냥 하나** 쓰세요. `%%` 로 쓰면 화면에 `%%` 가 그대로 나와 검증이 깨집니다
- `%%` 가 필요한 것은 **인자가 2개 이상일 때뿐**입니다
- `%` 뒤에 `s d i f j o O c` 가 안 오면 인자가 몇 개든 그냥 `%` 입니다
- 위험한 것은 **`%s`·`%d` 조합**과 **`%%`** 입니다
표는 `·` 나 `—` 로 잇거나, 주석으로 그리세요.

## 4. 문체

- **한글.** 전문용어는 한글로 풀고 영어를 괄호로: `색인(index)`
- 짧은 문장. 한 줄에 한 가지
- 존댓말 (`~합니다`)
- 강조는 `★` (중요), `★★` (매우), `★★★` (여기서 틀리면 사고)
- 표 이름·칸 이름은 **한글**로 씁니다 (읽기 쉬우라고). 회사에선 영어를 많이 쓴다는 것도 한 번 언급
- 변수명도 한글을 씁니다: `const 설비목록 = ...`
- "~할 수 있습니다" 보다 "~합니다". 재 봤으면 "재 봤습니다"

## 5. 실행 환경

### 01~06단원 — PGlite (설치 0)

```js
import { PGlite } from "@electric-sql/pglite";
const db = await PGlite.create();          // 메모리에만
const db = await PGlite.create("./내디비"); // 폴더에 저장 (파일 아니라 폴더입니다)
```

**PGlite 0.5.7 = PostgreSQL 18.3 (WASM).** 진짜 Postgres 입니다.
시작에 0.9초쯤 걸립니다. 파일 맨 위에 오래 걸린다고 적어 두세요.

```js
await db.query("SELECT * FROM 설비 WHERE 라인 = $1", ["A"]);
//   → { rows, fields, command, affectedRows, rowCount }
//   ★ 파라미터는 $1, $2 입니다. ? 가 아닙니다 (그건 MySQL/SQLite)
//   ★ query 는 세미콜론으로 이은 두 문장을 못 받습니다
//     → "cannot insert multiple commands into a prepared statement"

await db.exec("CREATE TABLE ...; INSERT INTO ...");
//   → 여러 문장 가능. 결과 배열을 돌려줍니다

await db.transaction(async (tx) => { await tx.query(...); });
//   → 콜백이 던지면 자동 롤백. 정상 종료면 커밋
```

**★ PGlite 는 연결이 하나뿐입니다.** 그래서 동시성·격리수준·락 실습은 못 합니다.
그건 07단원에서 Docker Postgres 로 합니다.

### 07~10단원 — Docker

```bash
docker compose up -d      # postgres:18-alpine (5434), mysql:8.4 (3307)
```

포트가 5432/3306 이 아닙니다. Postgres 는 **5434**, MySQL 은 **3307** 입니다.
★ 계정·DB 이름도 영어입니다: `factory` / `secret` / `factory_db`. (도커가 한글 컨테이너 이름을 거절합니다) 이미 깔린 DB 와 안 부딪히게 비켜 놨습니다.

```js
import pg from "pg";
const 연결 = new pg.Client({ host: "127.0.0.1", port: 5434, user: "factory", password: "secret", database: "factory_db" });
await 연결.connect();
```

**Docker 가 없는 사람을 위해** 파일 맨 위에 이렇게 적으세요.

```js
// ★ 이 파일은 Docker 가 필요합니다.  docker compose up -d
```

그리고 연결 실패를 잡아서 안내하고 정상 종료하세요. 검증이 깨지면 안 됩니다.

## 6. ★ 실측해 둔 것 (그대로 쓰세요, 다시 재도 됩니다)

### PGlite 타입이 자바스크립트로 올 때

| Postgres | JS | 주의 |
| --- | --- | --- |
| `INT` / `SMALLINT` | `number` | |
| `BIGINT` | **`bigint`** | ★★ `JSON.stringify` 가 **터집니다** |
| `NUMERIC` / `DECIMAL` | **`string`** | ★★ `"1.50"`. 계산하려면 바꿔야 합니다 |
| `REAL` / `DOUBLE PRECISION` | `number` | 0.1+0.2 문제 있음 |
| `BOOLEAN` | `boolean` | |
| `DATE` | `Date` | ★ UTC 자정으로 옵니다. 시간대 함정 |
| `TIMESTAMPTZ` | `Date` | |
| `JSONB` | `object` | 자동 파싱 |
| `TEXT[]` | 배열 | |
| `UUID` | `string` | |

`NUMERIC` 이 문자열인 것과 `BIGINT` 가 `bigint` 인 것은 **02단원에서 반드시 다루세요.**
돈 계산에서 사고가 납니다.

### 에러 객체

```
e.name = "error"
e.code = Postgres SQLSTATE

  42601 문법        42P01 없는 표     42703 없는 칸    42883 함수/연산자 없음
  22P02 타입        23502 NOT NULL   23505 중복       23514 CHECK
  23503 외래키 위반 (그리고 ON DELETE NO ACTION 이 막을 때)
  23001 ★ ON DELETE RESTRICT 가 막을 때 — 23503 이 아닙니다
  25P02 실패한 트랜잭션에서 계속 시도    40001 직렬화 실패   40P01 데드락
  428C9 IDENTITY ALWAYS 에 직접 INSERT   42P20 윈도우 함수를 WHERE 에

★★ RESTRICT 와 NO ACTION 은 같은 것이 아닙니다. 실측했습니다.

  ON DELETE RESTRICT   → 23001
  ON DELETE NO ACTION  → 23503

  DEFERRABLE INITIALLY DEFERRED 를 걸면 차이가 드러납니다.
    NO ACTION  → 검사가 커밋까지 미뤄져서 **통과**합니다
    RESTRICT   → 미뤄도 **즉시 막힙니다** (23001)

  "둘은 사실상 같다" 고 설명한 자료가 많은데 틀렸습니다.
e.message = 'syntax error at or near "SELEC"'
```

### 파일 저장 vs DB (01단원에서 잰 값)

|  | 10만 건 | 100만 건 |
| --- | --- | --- |
| JSON 파일 크기 | 6.4 MB | 65.6 MB |
| JS 힙에 올리면 | 18 MB | 185 MB (2.8배) |
| 1건 수정 — 파일 | 92 ms | 1,467 ms |
| 1건 수정 — DB | 0.5 ms | **0.4 ms (안 느려짐)** |
| 1건 조회 — 파일 | 61 ms | 776 ms |
| 1건 조회 — DB | 0.38 ms | 0.35 ms |
| 파일에 20건 동시 쓰기 | **1건만 남음** | |

★ 메모리는 **깨끗한 자식 프로세스**에서 재야 합니다. 같은 프로세스에서 재면 0 이 나옵니다.
